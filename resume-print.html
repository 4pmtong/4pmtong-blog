Agent Runtime & Stability
  • Long-horizon task reliability: checkpointed execution state, automatic recovery from mid-task failures (model timeouts, tool errors, crashes), idempotent retries — agents resume instead of restarting
  • Real-world execution, not chat: agents control the browser, terminal, and file system end-to-end — with sandboxing, per-tool error containment, and human approval gates for destructive actions
  • Concurrency: parallel multi-agent execution with inter-agent state coordination, backpressure on tool calls, context-window budget management

Architecture & Infrastructure
  • Dynamic task decomposition: planner builds a DAG of subtasks dispatched to specialized agents (browser, terminal, document, multimodal) in parallel
  • One codebase, two deployments: fully local self-hosted (Docker, data on-device) and managed cloud — forcing clean abstractions at every layer
  • Model-agnostic LLM gateway: routing across cloud APIs and local inference, with cost controls, fallback chains, abuse prevention
  • Backend: Python/FastAPI, PostgreSQL, Redis — async task processing, credit/quota systems
  • Mobile RL environments for agent training and evaluation

Design philosophy: the durable layer of the AI stack isn't the agent — it's the environment it runs in. Eigent's workspace is a configurable execution environment defining what agents can see, use, and act on.
